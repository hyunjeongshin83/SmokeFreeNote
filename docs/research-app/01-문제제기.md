# 연구형 앱 · 1단계 「문제제기」 (2026-11-13 · 제안 · 앱에 반영 안 됨)

대표님 말씀(2026-11-13): 첫 연구는 **전부, 순서대로** — 금연 → 금주 → 복약·접종. 코어는 새 저장소, 리서치는 문헌 조사만(예산 한도를 정한 뒤).
이 문서는 `docs/RESEARCH-APP.md` 의 ① 단계를 세 연구에 대해 채운 초안입니다. 코드·데이터 이동 없음. 연구 질문은 **제안**이며 대표님·교수님이 고칩니다.

각 칸은 「이미 앱이 모으는 것」(코드북에서 읽음)과 「모자란 것」을 나눠 적었습니다. 근거 문헌은 3단계(리서치)에서 채우므로 여기에는 **문헌을 인용하지 않습니다.**

## 연구 ① 금연 — 갈망이 올 때의 대처

| 칸 | 내용 |
|---|---|
| 현상 | 금연 앱 기록에는 「얼마나 당겼나 · 그때 기분 · 상황 · 넘긴 방법 · 결국 피웠나」가 한 줄씩 남는다 |
| 연구 질문(제안) | **갈망이 온 순간 고른 대처 방법이 같은 기록에서 「넘김」과 어떤 관계를 보이는가** (상황·기분·강도를 나눠서) |
| 대상 | 금연 시도 중인 성인 · 일반 담배 / 궐련형 / 액상 (`product_kind`) |
| 이미 모이는 것 | `records`(craving_level · mood · 상황 · 넘긴 방법 · slip) · `daily`(n_cravings · n_slips · n_held) · `participant`(하루 양 · 시작일 · 시도 횟수 · 흡연 기간) · `meds`(니코틴 대체제 종류·용량) · `measures`(날숨 CO 등) |
| 모자란 것 | 대처를 한 뒤 **얼마 만에 갈망이 줄었는지**(시간) · 기록하지 않은 순간(기록 편향) · 자가 보고 말고 객관 값(CO 측정은 선택 입력뿐) |
| 하지 않는 말 | 「이 방법이 효과 있다」「금연에 성공하게 해 준다」 같은 효과·치료 주장. 이 연구는 **기록 속 관계**를 본다 |
| 결정 질문 | 「갈망이 줄기까지 걸린 시간」을 기록하기에 한 칸 더하는 것은 화면 변경이라 따로 묻습니다 (이번 연구는 지금 기록 그대로로 시작할까요?) |

## 연구 ② 금주 — 마시고 싶은 순간의 상황

| 칸 | 내용 |
|---|---|
| 현상 | 금주 앱 기록에는 「마셨나/넘겼나 · 마시고 싶은 정도(0~10) · 기분 · 상황 · 대처 · 술 종류·양」이 남는다 |
| 연구 질문(제안) | **마시고 싶은 정도(0~10)가 높은 순간에 어떤 상황·기분이 함께 기록되고, 그 기록이 「마심」과 「넘김」으로 갈리는 차이는 무엇인가** |
| 대상 | 음주를 줄이거나 멈추려는 성인 (목표 `goal` 로 나눔) |
| 이미 모이는 것 | `records`(craving_0_10 · mood · 상황 · 대처 · kind · beverage · cups · alcohol_g_est) · `daily`(n_urges_held · n_drinks · alcohol_g_est · dry_day) · 술 9종(병·500cc 포함, 2026-11-11) |
| 모자란 것 | 같이 마신 사람 · 장소 · 시간대 정밀도(시 단위만) · 기록 안 한 순간 |
| 하지 않는 말 | **「안전한 음주량」「위험 음주 판정」「운전해도 된다」류 문구 일절 없음.** `alcohol_g_est` 는 「대략」이며 기준이 아니다. 중독·진단 판정 안 함 |
| 결정 질문 | 연구 ①과 같은 변수 이름(`craving`, `mood`, `trigger`, `coping`)으로 맞춰 두는 것을 코어의 첫 과제로 해도 될까요? (두 앱의 코드북을 합치는 작업, 지금 파일은 안 바뀜) |

## 연구 ③ 복약·접종 — 알림과 기록

| 칸 | 내용 |
|---|---|
| 현상 | 메디노트: 복약 일정·알림·복용 기록, 접종 시기 알림. 백신노트: 예진·판정 레코드와 설문 응답 |
| 연구 질문(제안, **미확정**) | **알림이 울린 뒤 복용·접종 기록이 이어지기까지의 시간 분포** (기록이 있는 사람 안에서만) |
| 대상 | 복약·접종 알림을 켠 성인 |
| 이미 모이는 것 | 메디노트: 복용 기록은 **기기 안(localStorage)에만** 있고 연구용 내보내기 경로가 없음. 백신노트: Firestore · PostgreSQL 에 응답이 있음(**변경·삭제·이동 금지**) |
| 모자란 것 | 메디노트에 연구 동의·가명 ID·내보내기가 **아직 없음**(건강 데이터가 어디로 가는지 정하는 일이라 법적 검토가 걸림, CLAUDE.md §2) · 백신노트는 읽기 전용으로만 분석 가능 |
| 하지 않는 말 | 접종 권장·금기 판정, 「부작용 모니터링」「위험 알람」「진단」 문구. 임상 판정 로직은 건드리지 않음 |
| 결정 질문 | ③은 데이터 쪽 결정(메디노트 연구 경로 신설 · 백신노트 읽기 전용 분석)이 먼저입니다. **①②를 코어에 태운 뒤 ③을 시작해도 될까요?** (예/아니오) |

## 다음 단계 (2단계 「측정 목적」)

세 연구의 변수를 한 표로 묶습니다 — 이름 · 단위 · 코드 · 어느 앱에서 오나 · 비어 있는 이유. 금연·금주는 이미 코드북이 있어 합치는 일이고, ③은 위 결정 뒤에 적습니다.
리서치(3단계)는 문헌 조사만 하며 참여자 데이터는 모델에 보내지 않습니다. 예산 한도는 키가 필요해지는 시점에 다시 정합니다.
