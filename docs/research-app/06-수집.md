# 연구형 앱 · 6단계 「수집」 (2026-11-13 · 제안 · 앱에 반영 안 됨)

여기서부터 **데이터가 기기 밖으로 나가는 길**이 나옵니다. 그래서 「어떻게 만들까」보다 **「무엇이 갖춰져야 켜는가」** 를 먼저 정합니다. 이 문서는 코드를 바꾸지 않고, **동의 문구를 짓지 않습니다**(IRB 가 승인한 전문만 쓴다 — `research-config.js` 규칙).
근거는 저장소의 `research.js` · `research-config.js` · `docs/RESEARCH-LAB.md` · `docs/apps-script/research-sink.gs` · `SmokeFree_app.html` 의 연구 참여 칸을 읽은 것입니다. **Apps Script 실행·시트 기록은 확인하지 못했습니다**(RESEARCH-LAB.md 도 같은 한계).

## 1. 지금 있는 것 (읽고 확인)

```
참여자 폰 ─ 동의 후 켬 ─ POST(JSON) ─▶ 연구실 Apps Script 웹앱 ─▶ 연구실 Google 시트 (participant · records · measures · daily · meds)
```

- **길이 둘**: 연구실로 보내기(`labUrl`) · 참여자 본인 Drive(`clientId`, drive.file 권한). 둘 다 **기본 꺼짐**(`enabled:false`).
- **관문**: `enabled` · 보낼 곳(`labUrl` 또는 `clientId`) · `consentText` · `consentVersion` · **`irb`**(2026-11-14 대표님 결정으로 더함 — 비었거나 공백뿐이면 준비 안 됨)가 모두 채워져야 화면에 「연구 참여」 칸이 **나타난다**. 하나라도 비면 칸이 안 보이고 아무 데도 접속하지 않는다.
- **보내기 직전 재확인**: 작업 세대(끄면 올라감)와 **그 순간 저장소에 적힌 동의의 버전**(`consented()`)을 다시 본다. 문구 버전이 바뀌면 이전 동의는 효력이 없다.
- **보내는 것**: 무작위 번호(`P-xxxxxxxx`) + 숫자 표. 이름·연락처·「나의 이유」·검사 장소·기기 이름·사진은 **들어가지 않는다**. 보낼 때마다 그 번호의 줄을 **통째로 바꾼다**(중복 없음).
- **끄기·지우기**: 끄면 진행 중 요청을 중단. 「보낸 자료 지우기」는 지우라는 **요청**(`delete`)을 보내고, 실패하면 참여는 꺼진 채 화면에 알린다.
- 앱 화면의 안내 문구는 보내는 곳(연구실/Drive)에 맞춰 바뀐다(`SmokeFree_app.html` 1669~1672행) — 「서버로 안 간다」류 사실과 다른 문구는 없다.

## 2. 켜기 전 체크리스트 — 누가 무엇을

| # | 갖춰야 할 것 | 누가 | 저장소에 있나 |
|---|---|---|---|
| 1 | IRB 승인(승인번호) | 교수님 | **없음** (`irb:""`) — 비어 있으면 **코드가 켜지 못하게 막음** |
| 2 | 동의 문구 전문 + 버전 이름 | IRB 가 승인한 것을 교수님이 | **없음** — 지어내지 않는다 |
| 3 | 연구실 Google 시트 + Apps Script 배포 → `…/exec` 주소 | 연구실 | 코드는 있음 (`research-sink.gs`), **배포·시험 안 됨** |
| 4 | 시험 번호로 한 번 보내 시트에 줄이 생기는지 확인 | 연구실 + 저(코드) | 안 됨 |
| 5 | 보관 기간·분석 사용 규칙 | IRB 문서 | 없음 |
| 6 | `enabled:true` | **교수님 확인 뒤** | `false` |

**이 여섯이 모두 되기 전에는 코드로 켜지 않습니다.** 1~2는 제가 대신 만들 수 없는 것입니다.

## 3. 동의 문구에 들어가야 할 항목 (문구가 아니라 목록 — IRB 용 점검)

저장소의 사실과 동의 문구가 어긋나지 않도록, 사실 쪽에서 확인된 것을 항목으로만 적습니다.

- 보내는 곳이 **연구실의 Google 시트**이고, 받는 길이 **Google Apps Script** 라서 보낼 때 **참여자의 IP 가 연구실 Google 계정의 로그에 남는다** (`RESEARCH-LAB.md` 한계)
- 보내는 것은 **숫자로 바꾼 기록**이고 이름·연락처·적은 글·사진은 제외 (`buildCodebook` `(제외)` 행)
- **기록 안 한 순간은 데이터에 없다** — 모든 결과에 「기록한 순간 안에서」가 붙는다 (3단계)
- 언제든 끌 수 있고, 지우기는 **요청**이며 **연구실이 시트에서 확인해야 확정**된다. 기기에서 보낸 뒤에는 앱이 회수할 수 없다
- 보관 기간 · 분석 사용 범위 · 문의처 — IRB 가 정함
- 이 앱은 진단·치료·판정을 하지 않는다

## 4. 점검에서 찾은 빈틈 (제안만 — 지금은 안 고침)

1. **보낸 이력이 마지막 한 건뿐입니다.** 상태에는 `lastSync` · `lastError` 만 있고 목록이 없다. RESEARCH-APP.md 의 「보낸 이력」은 아직 없는 기능이다. 제안: **이 폰 안에만** 보낸 시각·성공/실패 건수를 남기는 작은 이력(내용은 안 남김). 화면 변경이라 확인 뒤.
2. **주소를 아는 사람은 누구나 보낼 수 있다**(공개 코드). 받는 쪽이 번호 형식·크기·열 수를 거르고 `_log` 에 남기지만, 주소가 새면 새로 배포해 `labUrl` 을 바꿔야 한다 — 운영 절차로 적어 둘 일.
3. **6단계 코어화는 `labPost` 와 Drive 업로드를 같은 `send(sheets, pid, consent)` 모양으로 맞추는 일**이다. 지금도 같은 세대·동의 관문을 쓰므로 코어로 옮겨도 동작이 달라지지 않아야 하고, **바이트까지 같은 결과**로 증명한다(기존 `tests/research*.test.mjs`).
