# 연구형 앱 · 7단계 「분석·결과」 (2026-11-13 · 제안 + 합성 데이터 시험 · 앱에 반영 안 됨)

데이터가 한 줄도 나가지 않아도 할 수 있는 단계입니다. **실제 참여자 데이터는 쓰지 않았고**, 시드가 고정된 **합성(가짜) 기록**으로 「분석 → 결과 한 장」의 모양과 분석이 맞는지를 시험했습니다.
새로 더한 것: `tools/research-synth.cjs`(합성 기록 + 분석) · `tests/research-synth.test.mjs`(시험 2개). 앱·내보내기 코드는 바꾸지 않았습니다. `node --test tests/*.test.mjs` 119건 통과(기준선 117 + 2).

## 1. 분석이 하는 일 (연구 ①)

- 입력: 앱의 내보내기 `records` 표 그대로 (`research.js` `buildRecords` 를 거친 열 — 새 열 없음)
- 결과 변수: `lapse` = `slip`==1 (2단계의 방향 맞춤 — 금연은 `slip` 이 이미 1=피움)
- 조건 변수: 대처(`cope_*`) 하나씩
- 값: **(대처 있음) 피움 비율 − (없음) 피움 비율**, 그리고 **참여자 단위 부트스트랩 95% 구간**
- 왜 참여자 단위인가: 한 사람의 기록은 서로 닮았다. 기록 한 건 한 건을 독립으로 보면 구간이 지나치게 좁아진다(3단계의 결측 문제와 같은 계열의 주의).

## 2. 분석이 맞는지의 시험 — 양성·음성 대조

| 대조 | 만든 방법 | 기대 | 결과 |
|---|---|---|---|
| 양성 | 합성 기록에서 「산책」이 있으면 피울 확률을 25%p 낮춤 | 산책의 구간이 0 아래 | 통과 |
| 음성 | 효과를 심지 않음 (`--effect 0`) | 모든 구간이 0 을 포함 | 통과 |

두 대조가 모두 통과해야 분석이 「없는 효과를 만들지도, 있는 효과를 놓치지도」 않는다고 말할 수 있습니다. **이 시험은 계산이 맞다는 것이지 실제 효과가 있다는 것이 아닙니다.**

## 3. 「결과 한 장」 — 이 모양으로 낸다

```
※ 합성(가짜) 기록 — 시드 1 · 참여자 60명 · 기록 3102건 · 심은 효과: 산책 -25%p
대처 방법              있음     없음      차이   95% 구간 (참여자 단위 부트스트랩 400회)
cope_water      29.0%  29.0%    0.0%p   [-3.7, 3.8]
cope_breath     30.3%  28.5%    1.8%p   [-1.8, 5.5]
cope_walk       10.3%  35.2%  -24.9%p   [-28.5, -21.2]  ← 구간이 0 을 포함하지 않음
cope_brush      29.0%  29.0%   -0.0%p   [-2.9, 3.0]
cope_gum        29.7%  28.8%    0.9%p   [-2.9, 5.3]
cope_call       29.5%  28.8%    0.7%p   [-2.8, 4.8]
cope_hold5      28.8%  29.0%   -0.3%p   [-3.8, 2.9]

읽는 법: 「차이」는 피움 비율의 차(대처 있음 − 없음)이며 효과·인과가 아니다. 구간이 0 을 포함하면 이 표본으로는 방향을 말하지 않는다.
검증: 심은 효과(산책)를 되찾았다.
```

한 장에 반드시 들어가는 네 줄(제안):
1. **누구·얼마나**: 참여자 수 · 기록 건수 · 참여자별 기록 일수 중앙값 (3단계: 기록 안 한 순간 단서)
2. **표**: 위와 같은 대처별 비교 (있음 · 없음 · 차이 · 구간)
3. **읽는 법 한 줄**: 「차이는 피움 비율의 차이며 효과·인과가 아니다. 구간이 0 을 포함하면 방향을 말하지 않는다」
4. **한계 한 줄**: 「기록한 순간 안에서의 결과이며, 힘든 순간일수록 덜 적혔을 수 있다」

**쓰지 않는 말**: 「효과 있다」 · 「금연에 성공하게 해 준다」 · 「안전한 …」 · 판정·진단 표현. 표의 이름은 「관계」로 부릅니다.

## 4. 아직 안 한 것 · 알려진 한계

- **금주(연구 ②)** 는 같은 모양으로 `lapse` 를 `kind==2`(마심)로 맞추면 되지만, 이번에는 만들지 않았습니다 — 맞춤 규칙을 시험으로 먼저 못 박은 뒤 6단계 이후 코드 일로.
- 합성 기록은 **대처 칸이 서로 독립**이라 현실의 상관(스트레스+산책 등)을 모릅니다. 여러 대처를 한꺼번에 보는 모형은 만들지 않았습니다.
- 한 사람 안의 변화(같은 사람이 산책한 순간 vs 안 한 순간)를 보는 설계는 아직입니다 — 사람 간 차이와 섞이지 않게 하려면 필요한 다음 분석입니다(3단계 문헌의 방법).
- 실제 데이터에서는 기록 수가 적은 참여자가 많을 수 있어 구간이 넓어집니다. 합성 60명·3천 건은 **잘 모인 경우**입니다.

## 5. 결정 질문

1. 「결과 한 장」의 네 줄 구성과 「관계」라는 표현을 이대로 써도 될까요? (눈에 보이는 문구는 화면에 넣기 전에 따로 확인받습니다) (예/아니오)
2. 금주 분석(맞춤 규칙 + 시험)을 **다음에 먼저** 할까요, 아니면 한 사람 안 변화를 보는 분석을 먼저 할까요?
