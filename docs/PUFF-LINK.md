# 퍼프 연동 뼈대 (2026-10-21)

센싱이 가능한 전자담배의 퍼프를 자동으로 모으는 흐름의 **뼈대**입니다. 실제 기기와는 아직 연결하지 않았고,
**앱 본체(`index.html`)에는 연결하지 않았습니다.** 실험 화면 `labs/puff-link/index.html` 에서만 돕니다.
근거와 가정은 `docs/experiments/ecig-sensing/report.md` — 그 수치는 모두 시뮬레이션이며 실기기 측정이 아닙니다.

## 1. 있는 것

| 파일 | 내용 |
|---|---|
| `labs/puff-link/puff-core.js` | 순수 로직. 합치기(일련번호 중복 제거) · 누락 구간 · 완전성 · 하루 요약 · 니코틴 참고치 · 전주 대비 추세 · 카운터형 기기 · 저장 · **가짜 기기** |
| `labs/puff-link/index.html` | 실험 화면. 가짜 기기 연결 · 21일치 가짜 기록 · 오늘 요약 · 수집 상태 · 최근 7일 |
| `tests/puff-core.test.mjs` | `node --test tests/puff-core.test.mjs` — 18개. 핵심 로직을 일부러 망가뜨려 시험이 실패하는 것까지 확인함 |

화면은 기존 색·크기 토큰만 씁니다. 390px · 320px · 글자 200% 에서 가로 넘침 없음, 터치 단추 44px 이상, axe 위반 0 (이 환경의 Chromium 기준).

## 2. 저장

- `localStorage` 키 **`smokefree.puffs.v1`** 한 곳. 기존 기록 키(`smokefree.v1`)는 읽지도 쓰지도 않습니다 (시험으로 확인).
- 서버로 보내지 않습니다. 외부 글꼴·스크립트도 부르지 않습니다 (화면 실행 중 바깥 요청 0 으로 확인).
- 하루 약 200건 기준 약 100일치(2만 건)까지 보관하고 오래된 것부터 버립니다.

## 3. 시뮬레이션에서 이어받은 설계 규칙

| 규칙 | 근거 (report.md) |
|---|---|
| 기록은 기기의 **일련번호(seq)** 로 중복 제거. 실시간으로 받은 것을 재동기화로 또 받아도 한 번만 | §4.2 |
| 완전성 = 받은 수 ÷ (최대 seq − 최소 seq + 1). **끊겨 있는 동안에는 숫자를 주지 않고 「동기화 대기」** | 끊긴 중 표시의 39 % 가 5 %p 넘게 과대 |
| 전주 대비는 **앞선 2주**와 견주되, 기간이 덜 찼으면 합계가 아니라 **추적한 날수로 나눈 하루 평균**으로 비교(분모는 기록을 시작한 날부터 지금까지 — 퍼프가 없던 날도 진짜 0 으로 셈). 문턱 **20 %**, 양쪽 5일 이상 추적 필요 | 10 % 문턱은 자연 변동만으로 거짓경보 13~19 % |
| 추세는 **일련번호 누락을 채워 넣어** 계산. 두 기간의 경계에 걸친 누락은 **시간에 비례해 나눔**(가정: 누락이 그 시간 동안 고르게 퍼짐 — 밤에는 틀릴 수 있어 작은 오차가 남음) | 주 사이 완전성이 바뀐 것을 변화로 오해(거짓경보 72 %)하지 않게 |
| 하루 안에 **길이를 아는 퍼프가 일부뿐이면** 니코틴 참고치를 보여 주지 않음 | 일부만으로 하루를 대표시키면 과소 표시 |
| 퍼프 길이가 없는 기기(카운터형)는 니코틴 참고치를 만들지 않음 | §4.2 |
| 기기에 저장되는 퍼프는 **64건 이상** 을 권장 (16건은 하루 약 2.5 % 손실) | §4.2 |

## 4. 실기기를 붙일 때 맞춰야 할 모양 (`puff-core.js` 머리의 계약)

```
provider = { id, name, capabilities:{seq,duration,ringBuffer}, connect(), disconnect(),
             onPuff(cb({seq,t,d})), onLink(cb({connected})), readSince(seq) → Promise<[{seq,t,d}]> }
```

블루투스 코드는 **아직 넣지 않았습니다.** 기기의 서비스 UUID·데이터 형식이 정해져야 쓸 수 있고, 권한 요청 코드를
기기 없이 넣어 두면 검증할 수 없습니다. 안드로이드는 `BLUETOOTH_SCAN` · `BLUETOOTH_CONNECT` 권한과 네이티브 코드가 필요합니다.

## 5. 하지 않은 것 · 결정이 필요한 것

- **실제 기기 선택** — 연구용 센서인지 시판 기기인지, 그 기기의 데이터 형식. 사람이 정할 일입니다.
- **앱 본체에 넣기** — 홈 · 기록 · 통계 화면과 이 모듈을 어떻게 이을지는 손님이 보는 화면 변경이라 대표님 확인 대상입니다 (CLAUDE.md §2).
- **서버 저장 · 약사 공유** — 건강 데이터가 기기 밖으로 나가는 일이라 결정과 동의 설계가 먼저입니다.
- 화면 문구(추세 문장 포함)는 **시안**입니다. 판단·단정을 피하고 「참고치」를 밝혔을 뿐 확정 문구가 아닙니다.
- 니코틴 수치는 기화된 액상의 양입니다. 몸에 흡수된 양이 아닙니다.
