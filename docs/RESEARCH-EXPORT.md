# 연구용 Drive 저장 (엑셀)

대표님 결정 (2026-11-09 · 채팅): 저장은 **참여자 본인의 Google Drive** · 전송은 **자동** · 엑셀은 **앱 데이터를 수치로 바꾼 연구자료** · 동의 문구·IRB 번호는 **아직 없음**.

## 지금 상태

**꺼져 있습니다.** `research-config.js` 의 `enabled:false` 가 기본값이고, 아래가 모두 채워지기 전에는 화면에 「연구 참여」 칸이 보이지 않으며 아무 데도 접속하지 않습니다
(Google 스크립트도 불러오지 않습니다).

```
enabled          true
clientId         Google Cloud 콘솔의 OAuth 클라이언트 ID (비밀값 아님)
consentText      IRB 가 승인한 동의 문구 전문   ← 이 저장소에는 아직 없습니다. 지어내지 않았습니다
consentVersion   동의 문구의 버전 이름 (참여자가 어느 문구에 동의했는지 가리는 데 씀)
irb              IRB 승인번호   ← 이 저장소에는 아직 없습니다. **비어 있으면(공백만 있어도) 코드가 켜지 못하게 막습니다** (2026-11-14 대표님 결정)
```

## 데이터가 가는 길

```
참여자 폰 (localStorage smokefree.v1)
   └ 수치화 (research.js) ── .xlsx ──▶ 참여자 본인의 Google Drive  (파일 하나, 이름 「금연노트_연구자료.xlsx」)
```

- 연구실 서버·Firebase·Supabase 어디로도 가지 않습니다. **연구진은 이 길로는 자료를 자동으로 받지 못합니다.** 참여자가 파일을 공유해야 합니다 (연구실 Drive 로 모으는 길은 다음 단계 — 정하면 따로 만듭니다).
- Google 권한은 `drive.file` 하나입니다 — 이 앱이 만든 파일만 읽고 쓰며, 참여자 Drive 의 다른 파일은 볼 수 없습니다.
- 토큰은 메모리에만 둡니다 (저장하지 않음). 끄면 토큰을 취소합니다. 파일을 이 앱에서 지울 수도 있습니다.
- 이름·연락처·「나의 금연 이유」·검사 장소·기기 이름·사진은 파일에 넣지 않습니다. 참여자는 연구용 무작위 번호(`P-xxxxxxxx`, 이 기기에서 처음 켤 때 만듦)로만 구분됩니다.
- 저장 키 `smokefree.research.v1` (동의 시각 · 동의 문구 버전 · 연구 번호 · Drive 파일 id · 마지막 저장). 기존 키 `smokefree.v1` 은 건드리지 않습니다.

## 언제 보내나

- 켠 직후 한 번 (참여자가 누른 직후라 Google 로그인 창이 열릴 수 있음)
- 이후 기록이 바뀌면 8초 모았다가 자동으로, 마지막 전송 뒤 60초 안에는 다시 보내지 않음
- 앱을 열 때 동의한 상태이고 마지막으로 올린 뒤 **엑셀에 들어갈 내용(참여자 · 기록 · 측정값 · 일별 표 전체의 해시)** 이 달라졌으면 한 번 따라잡습니다 (닫아서 예약이 사라졌거나 연결이 없던 때의 기록).
- 올리는 중에 기록이 또 바뀌거나 다른 탭의 변경을 합쳤다면, 올린 것이 낡은 것으로 보고 끝난 뒤 한 번 더 올립니다. 다른 탭의 변경을 합칠 때도 올리기를 예약합니다.
- 파일을 찾고·만들고·덮어쓰는 구간은 같은 기기의 탭끼리 한 번에 하나만 합니다(Web Locks) — 참여자가 Drive 에서 파일을 지운 뒤 두 탭이 동시에 올려도 파일이 둘 생기지 않습니다.
- 파일 속성에 연구 번호(`sfPid`)를 달아, 같은 구글 계정으로 다른 기기·브라우저에서 켜도 번호가 맞는 파일만 찾습니다(서로 덮어쓰지 않음 — 파일은 번호마다 하나).
- 구글이 토큰을 거절(401)하면 그 토큰을 버려, 「지금 저장」을 다시 누르면 새로 로그인합니다.
- 일별 시트는 가장 이른 기록·시작일·**앞 시도의 시작일**부터 오늘까지이고, 5000일(약 13년)을 넘으면 가장 최근 5000일만 담습니다(codebook 에 적힘, records 시트는 줄이지 않음).
- 끄거나 「모든 기록 지우기」를 하면 **진행 중이던 로그인·조회·업로드 요청을 중단**합니다 (AbortController). 다른 탭에서 끄거나 지운 경우에도 이 탭의 예약과 진행 중인 요청을 멈춥니다 (storage 이벤트).
  이미 Google 에 도착한 데이터는 앱이 회수할 수 없습니다 — 파일은 참여자 Drive 에 있으므로 「Drive 파일 지우기」나 Drive 에서 직접 지웁니다.
- **전송 관문:** Drive 로 나가는 모든 요청은 `research.js` 의 `api()` 한 곳을 지납니다. 엑셀 만들기 같은 동기 작업이 모두 끝난 **fetch 직전**에서 ① 작업 세대가 그대로인지 ② 건강 정보를 싣는 요청이면 **그 순간 저장소에 적힌 동의**가 유효한지 마지막으로 확인합니다. 앞에서 확인한 결과를 믿지 않습니다(다른 탭이 그 사이 바꿨을 수 있음). 새 전송 경로를 만들면 반드시 이 관문(`gate`)을 넘겨야 합니다.
- **「Drive 파일 지우기」는 참여를 먼저 끕니다.** 예약·진행 중인 저장을 모두 중단한 뒤에 파일을 지웁니다. 지우는 동안 자동 저장이 새 파일을 만들 수 없고, 지우기가 실패해도 참여는 꺼진 채로 남으며 파일 정보가 남아 다시 지울 수 있습니다. 이미 파일이 없으면(404) 지운 것으로 봅니다.
- 동의 문구 버전(`consentVersion`)이 바뀌면 다시 동의하기 전까지 보내지 않습니다.
- **앱이 열려 있을 때만** 보냅니다 (백그라운드 전송 없음). Google 토큰은 약 1시간이라, 만료된 뒤에는 조용히 갱신을 시도하고 안 되면 「지금 저장」을 눌러 다시 연결하라고 화면에 보입니다.

## 엑셀 구성 (시트 6장 · 코드북은 파일 안에도 있음 · 코드북 v2 — 2026-11-11)

| 시트 | 내용 |
|---|---|
| participant | 연구 번호 · 피우는 것(1 일반 · 2 궐련형 · 3 액상) · 하루 평소 양 · 가격(원) · 금연 시작일 · 시도 횟수 · 흡연 기간(년, 선택) · 앱 전 금연 시도 횟수(선택) |
| records | 갈망 기록 한 줄씩. 날짜 · 시(0~23) · 요일 · 시도 번호 · 시작일부터 며칠째 · 세기(1~3) · 기분(1~3) · 상황 8개와 「상황 미입력」(각 0/1) · 옆에 흡연자 · 담배 구할 수 있음 · 넘긴 방법 7개(각 0/1) · 피움(0/1) · 기록 형식 |
| measures | 측정값 한 줄씩. 종류 코드(1 CO · 2 퍼프 · 3 키트 · 4 코티닌 · 5 의료기관 CO · 6 스티커 사용 · 7 걸음 · 8 심박 · 9 수면) · 값 |
| daily | 하루 한 줄. 기록 수 · 피운 수 · 넘긴 수 · 세기 평균 · 약 복용 · 스티커 사용 |
| meds | 약을 적은 한 번이 한 줄. 날짜 · 시 · 종류(1 패치 · 2 껌 · 3 사탕·트로키 · 4 바레니클린 · 5 부프로피온 · 9 그 밖) · 용량 mg · 개수 (VN-218-5 · 대표님 결정 2026-11-11) |
| codebook | 위 숫자가 무엇을 뜻하는지 |

- 날짜는 기기의 현지 시각 기준입니다. 시도 번호·며칠째·`day_index` 는 모두 **달력 날짜**로 셉니다 (시작한 날이 0).
- 옛 기록(`v` 없음)은 없는 칸을 빈 칸으로 둡니다 — 숫자를 지어내지 않습니다.
- 엑셀 파일은 외부 라이브러리 없이 이 앱이 직접 만듭니다 (`tests/research.test.mjs` 가 zip 구조와 CRC, 시트 내용을 확인합니다. 엑셀 읽기 도구(openpyxl)로 열어 시트가 읽히는 것도 확인했습니다 — 2026-11-11 코드북 v2 의 6장도 openpyxl 로 열어 meds 줄과 participant 새 두 열을 읽었습니다).

## 켜는 순서 (대표님이 하실 것)

1. **IRB 승인 문구**를 `consentText` 에 넣고 `consentVersion` 을 정합니다. 앱의 「연구 참여」 칸 소개 문구(「내 Google Drive 의 엑셀 파일 하나에 자동으로 저장돼요…」)도 함께 확인해 주세요 — 눈에 띄는 문구입니다.
2. **Google Cloud 콘솔**에서 (화면 문구는 바뀔 수 있어 실제 화면에서 확인하세요)
   1. 프로젝트를 고르거나 만들고, 「API 및 서비스 → 라이브러리」에서 **Google Drive API** 를 사용 설정합니다.
   2. 「OAuth 동의 화면」: 사용자 유형 **외부**, 앱 이름·지원 이메일을 적고, 범위에 `…/auth/drive.file` 만 추가합니다.
   3. 게시 상태를 **프로덕션** 으로 둡니다 (테스트 상태는 등록한 시험 사용자만 쓸 수 있고 토큰이 짧게 만료됩니다). `drive.file` 은 민감하지 않은 범위라 별도 심사가 필요 없을 가능성이 높지만, 앱 이름·로고 확인이 요구되는지는 콘솔 안내를 따르세요.
   4. 「사용자 인증 정보 → OAuth 클라이언트 ID 만들기」: 유형 **웹 애플리케이션**, 「승인된 JavaScript 원본」에 앱이 열리는 주소(예: `https://…github.io`)를 넣습니다. 리디렉션 URI 는 필요 없습니다.
   5. 만들어진 **클라이언트 ID** 를 `research-config.js` 의 `clientId` 에 넣습니다. (비밀번호·클라이언트 보안 비밀은 필요 없고, 저장소에 넣지 않습니다.)
3. `enabled:true` 로 바꾸고 PR 로 올립니다.

## 아직 확인하지 못한 것

- **진짜 Google 로는 시험하지 못했습니다.** 시험은 가짜 Google 서버(로그인 창 · Drive 목록 · 업로드)로 했습니다 — 켜기 전에는 접속 없음, 켠 뒤 목록→업로드, 새 기록 뒤 같은 파일 덮어쓰기, 끄면 중단·토큰 취소, 로그인 실패 시 켜지지 않음.
  콘솔 설정을 마친 뒤 실제 계정으로 한 번 켜 보고 엑셀이 Drive 에 생기는지 확인해야 합니다.
- iOS 사파리(홈 화면 앱)에서 Google 로그인 창이 열리는지, 안드로이드 크롬에서 조용한 토큰 갱신이 되는지는 실기기에서 확인하지 못했습니다.
- 안드로이드 셸(WebView) 앱에서는 Google 로그인 창을 쓸 수 없어 이 칸을 숨깁니다 (`window.Native`). 연구용 저장은 웹(브라우저·홈 화면 앱)에서만 됩니다.
- 연구진이 자료를 모으는 길(연구실 Drive · 공유 방식)은 정하지 않았습니다.
- 앱의 안내 문구 「앱이 서버로 보내지 않아요」(시작 화면)는 기본값에서는 사실이라 그대로 둡니다. 켠 사람에게는 「연구 참여」 칸이 따로 설명합니다.
