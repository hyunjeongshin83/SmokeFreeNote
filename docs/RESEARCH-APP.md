# 연구형 앱 — 설계 제안 (2026-11-12 · 제안 · 앱에 반영 안 됨)

대표님 말씀(2026-11-12): 이 앱들은 **연구형 데이터 전송 리포트**를 위한 것이다. 네 앱에서 공통된 것을 뽑아 **연구형 앱**을 만든다.
연구형 앱의 형식은 **문제제기 → 측정 목적 → 리서치 → 센싱 하드웨어 선정 → 연결 → 수집 → 데이터 분석 후 의미 있는 결과**이고, **이 흐름에 필요한 메뉴가 계속 추가되는 것**이 앱이다.
전송 길은 **연구실 Google 시트를 유지하고, 어댑터로 넓힌다**(결정).

이 문서는 제안입니다. 코드는 아직 없고, 데이터가 기기 밖으로 나가는 길은 모두 닫힌 채입니다(CLAUDE.md §2 · §3).

## 1. 흐름이 곧 메뉴 — 단계 7개

| 단계 | 메뉴가 하는 일 | 지금 이미 있는 것 (근거) |
|---|---|---|
| ① 문제제기 | 무엇이 문제인가 · 연구 질문 한 줄 · 대상 | 리서치 이슈 `[리서치]` · 금연노트 `docs/DESIGN.md` 0절 |
| ② 측정 목적 | 무엇을 재서 무엇에 답하나 — **변수 정의 표**(이름 · 단위 · 코드) | `research.js` 코드북(`buildCodebook`) · 메디노트 `metric_defs`(LOINC·UCUM) |
| ③ 리서치 | 근거 문헌 · 경쟁 · 선행 시험 모음 | `docs/COMPETITORS.md` · `docs/DATA-MODEL.md` · 리서치 이슈 |
| ④ 센싱 하드웨어 선정 | **기기 카탈로그**(무엇을 어떻게 재나 · 정확도 · 검증 상태 · 연결 방식) | `docs/DEVICES.md` · `iqos-ble.js`(금연노트) · 메디노트 BLE·Health Connect·HealthKit |
| ⑤ 연결 | 기기·앱 연결 상태 · 권한 · 가짜 기기로 점검 | `labs/puff-link/`(가짜 기기) · 메디노트 「건강기기 연결」 시트 |
| ⑥ 수집 | 기록 → 가명 ID → 동의 확인 → 전송(어댑터) · 보낸 이력 | `research.js`(동의·가명 ID·Drive/연구실 전송) |
| ⑦ 분석·결과 | 일별·참여자별 요약 · 리포트 내보내기(XLSX) · 의미 있는 결과 한 장 | `buildDaily` · `buildParticipant` · 상담자 요약(`pro/`) · 백신노트 연구 포털 |

**메뉴는 목록(레지스트리)에 한 줄 더하면 늘어납니다.** 메뉴 하나 = `{id, 단계, 이름, 상태(초안·시험중·사용), 필요한 것, 화면 파일}`. 앱 본체는 목록만 읽어 그리므로 새 메뉴가 기존 화면을 건드리지 않습니다.

## 3. 코어 — 앱마다 다른 것만 남기고 뽑기

```
core/
  consent      동의 문구 · 버전 · 동의했는지 확인(「동의 없이는 한 줄도 안 나감」을 한 곳에서)
  pid          가명 ID 만들기
  schema       변수 정의(이름 · 단위 · 코드 · 설명) → 코드북 시트 · 열 순서 자동
  sheets       기록 → 표(기록 · 일별 · 참여자 · 코드북) — 앱이 「변수 정의」만 주면 만들어 줌
  xlsx         XLSX 쓰기(zip · CRC32 · 시트 XML · 수식 시작 글자 방지)
  transport/   전송 어댑터 — 같은 모양(`send(sheets, pid, consent)`)의 갈래
      labSheet   연구실 Apps Script(지금 있음 · 기본 닫힘)
      drive      참여자 본인 Drive(지금 있음 · 기본 닫힘)
      supabase   메디노트 쪽(나중 · 별도 결정)
      firestore  백신노트 쪽(나중 · 별도 결정 · 연구 데이터 변경·삭제 금지 규칙과 충돌 안 하게 새 컬렉션)
  sensors/     센서 어댑터 — 같은 모양(`connect() · read() · status()`)
      ble · healthconnect · healthkit · manual · fake(시험용 가짜 기기)
menus/         메뉴 레지스트리(1절) · 메뉴마다 화면 파일 하나
apps/          앱별 「변수 정의」와 문구만 — 금연 · 금주 · 메디 · 백신
```

**원칙**
- 전송 어댑터는 **모두 기본 닫힘**입니다. 동의 문구·IRB·설정이 채워지기 전에는 기록이 기기 밖으로 나가지 않고 화면에도 안 보입니다(지금 `enabled:false` 와 같음). 「서버로 안 간다」고 쓰지 않습니다.
- 코어는 **데이터를 보지 않습니다** — 변수 정의와 어댑터를 받아 표를 만들고 보낼 뿐이라 건강 데이터 값이 이슈·로그에 남지 않습니다.
- 앱이 주는 「변수 정의」가 바뀌면 코드북 버전이 올라갑니다(지금 `CODEBOOK_VERSION`).
- 코어는 **지금 내보내기와 바이트까지 같은 결과**를 내는지로 검증합니다(2단계).

## 4. 순서 — 한 번에 하지 않습니다

| 단계 | 하는 일 | 데이터 | 확인 |
|---|---|---|---|

| 2 | 메뉴 레지스트리 + 껍데기(7단계 화면 · 비어 있어도 됨) · 어댑터 틀 | 안 나감 | 화면 |
| 3 | 센싱 하드웨어 카탈로그 메뉴(④) — `DEVICES.md` 를 메뉴로 · 연결 점검(⑤) 가짜 기기 | 안 나감 | 화면 |
| 4 | 분석·결과 메뉴(⑦) — 일별·참여자별 요약 · 리포트 한 장 | 안 나감 | 화면 |
| 5 | 연구실 시트 어댑터를 실제로 켜기 | **나감** | IRB · 동의 문구 · Apps Script 배포 — 대표님·교수님 |

5단계 앞에는 아무것도 기기 밖으로 나가지 않습니다.

## 5. 정해주셔야 할 것

1. **코어를 둘 곳** — 새 저장소(예: `ResearchCore`)를 만들면 네 앱이 가져다 쓰고 갈라지지 않지만 GitHub 에 새로 만들어집니다. 아니면 금연노트 저장소 안 `core/` 폴더로 시작해(새 저장소 없이) 금주노트가 복사해 씁니다(나중에 갈라질 위험). 지금 문서는 어느 쪽이든 읽히게 썼습니다.
2. **「네 앱」 확정** — 위 표의 읽기(금연 · 금주 · 메디 · 백신)가 맞는지.
3. **첫 연구 한 가지** — 문제제기부터 끝까지 한 번 태워 볼 연구(금연 · 금주 중 하나가 가장 가깝습니다). 첫 연구가 정해져야 ② 변수 정의와 ⑦ 결과의 모양이 정해집니다.
4. **IRB 동의 문구·승인번호** — 5단계 전에 필요합니다. 저장소에는 아직 없고 지어내지 않습니다.

## 6. 하지 않는 것

실제 참여자 데이터를 이슈·문서에 옮기기 · 진단·판정 문구 · 「안전한 …」 말하기 · 동의 없이 전송하기 · 백신노트 연구 데이터(설문 응답 · `vaccine_note_records`)의 변경·삭제·이동.
